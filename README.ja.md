# UNI2 Frame Meter

[English](README.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md)

『UNDER NIGHT IN-BIRTH II Sys:Celes』のトレーニングモード向けフレームタイムラインです。両プレイヤーのフレームごとの行動状態をゲーム画面下部に表示し、発生、攻撃判定、硬直、硬直差、無敵、キャンセル可能時間を直感的に確認できます。

**0.6.0-rc.2 はネイティブフックの候補版です。** 32-bit の補助プログラムが Frame Meter DLL をゲームに読み込みます。DLL は元の戦闘更新関数から tick ごとの完全なスナップショットを取得し、共有メモリで独立したオーバーレイへ渡します。元のゲーム関数は通常どおり実行されます。戦闘のシミュレーションやゲームスクリプトの変更は不要です。前候補版はユーザーのトレーニングモードで動作確認済みです。今回の新しい状態表示には実機確認が必要です。

## 主な機能

- 2段表示：上段が1P、下段が2P。
- 発生、攻撃判定、硬直、行動不能時間を表示。
- キャンセル属性、無敵属性、左右両方向のガード補助、有効な飛び道具を任意で表示。
- 同一フレームの複数属性を色のレイヤーで同時表示。
- 連続する色区間のフレーム数を自動表示。
- 両者が行動可能になった後も結果を保持し、操作を止めて確認可能。
- 独立した透明オーバーレイに、ネイティブのゲーム状態スナップショットを表示します。

## 動作環境

- Windows 10 または Windows 11（64-bit）
- Steam版 UNDER NIGHT IN-BIRTH II Sys:Celes
- ウィンドウまたはボーダーレス表示モード

この候補版は、解析済みの 32-bit `uni2.exe` に対応しています。

- ファイルサイズ：**6,921,216 バイト**。
- SHA-256：`4ebed985ecbf330ab8e495573361e49df20bb555263289d1aff5425fac9b7ed9`。

補助プログラムは EXE の識別情報、読み込まれたイメージ、フック関数の入口を確認してから接続します。未対応の EXE ではフックを設置せず、エラーを表示します。ゲーム更新でネイティブ関数やデータ構造が変わった場合は、互換性対応が必要です。従来の EXE パターン検索と外部ポーリングを元の更新関数からのスナップショットに置き換えましたが、ゲームバージョンに依存しなくなるわけではありません。

## インストールと使用方法

1. [Releases](https://github.com/geturin/UNI2FrameMeter/releases) から候補版 ZIP をダウンロードし、すべて展開します。
2. 次の4ファイルを同じフォルダーに置きます：

```text
UNI2FrameMeter.exe
frame_semantics.json
uni2-frame-meter-host.exe
uni2-frame-meter.dll
```

3. ゲームを起動してトレーニングモードに入ります。
4. `UNI2FrameMeter.exe` をダブルクリックします。
5. ゲームへ戻ると、ゲーム画面下部にタイムラインが表示されます。

タイムラインはゲームが前面にあり、最小化されていない間だけ表示されます。`UNI2 Frame Meter` コントロールウィンドウを閉じると、データ取得とオーバーレイが終了します。小さなフックはゲームが終了するまで残ります。以前の DLL を再利用しないよう、**ツールを更新する前にゲームを再起動してください**。

配布パッケージには Python/Tk の実行環境が含まれるため、Python の別途インストールは不要です。32-bit の補助プログラムが 32-bit ゲームへの注入を行い、オーバーレイは独立した 64-bit アプリケーションとして動作します。

データ取得はゲームのトレーニング戦闘モードに限定しています。他のモードでは元の関数を通常どおり実行し、フレームデータは記録しません。

## タイムラインの読み方

- 上段が1P、下段が2Pです。
- 1マスがゲーム内の1フレームです。
- 最後に記録されたマスの右端を白い線で示します。
- 第1色が連続している間、そのフレーム数を1Pは上、2Pは下に表示します。
- 両者が行動可能で、有効な飛び道具や左右両方向のガード補助を表示する必要がない場合、タイムラインを停止して結果を保持します。
- 短い停止後に再び行動すると、経過時間は黒いマスになり、2つの行動を直接つなぎません。
- デフォルトでは60F連続で何も起きないと、次の行動から左端で新しい記録を開始します。
- タイムラインが満杯になると循環し、黒い間隔で新旧の内容を区別します。

基本色は行動不能、発生、攻撃判定、硬直を表します。キャンセル、無敵、飛び道具などの追加属性は同じマス内にレイヤー表示されます。色は設定ファイルで変更できます。

各マスはゲーム本来の戦闘更新の経過フレームです。メニューの一時停止や描画だけの呼び出しでは進みません。ネイティブのスロー・停止期間を含むため、表示時間は停止時間をすべて除いた技固有のフレーム数ではありません。F8 診断記録には元のラウンド段階とスケジューラの値も保存されます。

行動可能状態には確認済みのネイティブ判定を使い、旧版の着地・ガード復帰の近道判定は削除しました。キャンセル帯は取得したネイティブ条件を表し、各キャラクターの完全な入力成立条件ではありません。欠落したスナップショットは補間せず、タイムラインをリセットして短い通知を表示します。診断カウンタは F8 記録に残ります。

## コントロールウィンドウ

ツールを起動すると小さなコントロールウィンドウが開きます。項目をチェックまたは解除すると、その属性をすぐに表示・非表示にできます。

`two_way_guard` は初期設定で有効で、左右両方向のガード補助を紫色で示します。例えば1Pのクオンが対象の623技を使うと、補助を受ける2Pの段に表示されます。2Pが自由に行動できる間も表示され、この色は硬直を意味しません。相手本体の攻撃に対する方向補助であり、中段・下段などの防御条件は引き続き必要です。独立した飛び道具にはそれぞれの方向属性が適用されます。

- 変更はすぐに反映されます。
- 選択内容は `frame_semantics.json` に自動保存されます。
- グレーの項目は現在利用できず、有効にできません。
- `cs_cancel` は未完成のため選択できません。Chain Shift が使用可能かどうかを、この表示で判断することはできません。
- コントロールウィンドウを閉じるとタイムラインも終了します。

### 詳細な状態表示

チェック項目の右側に、タイムラインと同じ色の四角を表示します。未選択・使用不可の項目は空枠になります。累積 tick / sequence 数字は表示しません。

| 項目 | 意味 | 初期値 |
| --- | --- | --- |
| Hitstun / Guardstun | 被弾・ガード中の拘束 | ON |
| Down state | 拘束中のネイティブダウン状態（復帰区間を含む） | ON |
| Captured | 投げなどによる拘束 | ON |
| Hitstop | キャラクターの停止タイマーが正 | OFF |
| Counter-hit vulnerable | CH を受け得るフラグ。CH 成立を保証する表示ではありません | OFF |
| Airborne / Crouching | 時限上書きを含む空中・しゃがみ姿勢 | OFF |
| Ground assault / Air assault | ゲームの地上・空中 Assault 動作フラグ | OFF |

拘束の詳細色を非表示にすると、通常の行動不能色に戻ります。他の項目は追加レイヤーです。Hitstop は主色や経過フレーム数を変更しません。CH 成立には相手の技やトレーニング設定も関係します。ダウンの硬／軟区分、完全な CS 条件、dash/backdash、着地硬直、受け身可能時間は判定していません。

更新時に既存の `frame_semantics.json` を残すと、色・表示選択・タイムライン設定を維持できます。新項目を自動的に追加し、次の表示変更時に保存します。内蔵判定の定義はアプリケーションのバージョンに合わせて更新します。

## 設定ファイルの編集

`frame_semantics.json` はプログラムと同じフォルダーにあります。標準JSON形式です。ツールを終了してから編集し、変更前にバックアップを作成することを推奨します。

### タイムライン設定

```json
"timeline": {
  "length_frames": 120,
  "idle_reset_frames": 60,
  "wrap_gap_frames": 5,
  "max_width_pixels": 1440,
  "current_frame_border_color": "#ffffff",
  "show_primary_run_counts": true,
  "primary_run_count_color": "#ffffff",
  "primary_run_count_font_size": 9
}
```

- `length_frames`：タイムラインのマス数。
- `idle_reset_frames`：次の行動を新しい記録にするまでの空きフレーム数。
- `wrap_gap_frames`：循環時に新旧の内容を分ける黒いマス数。
- `max_width_pixels`：タイムラインの最大幅。
- `current_frame_border_color`：最新フレームのマーカー色。
- `show_primary_run_counts`：連続区間のフレーム数表示を有効にします。
- `primary_run_count_color`：フレーム数文字の色。
- `primary_run_count_font_size`：フレーム数文字の大きさ。

### 色と順序の変更

各状態は `tokens` 内で定義されています：

```json
"attack": {
  "order": 50,
  "color": "#f0ad38"
}
```

- `color` は `#RRGGBB` 形式です。
- `order` が小さいほど、マス内の上側に表示されます。
- 存在しない属性や非表示の属性は空のレイヤーを残しません。

### 任意表示項目

任意項目は `external_attributes` にあります：

```json
{
  "token": "full_invincible",
  "display": true,
  "status": "confirmed",
  "description": "..."
}
```

- `display` を `true` にすると表示、`false` にすると非表示になります。
- `status` が `confirmed` の項目は変更できます。
- `status` が `incomplete` の項目は現在有効にできません。
- `description` は説明用であり、変更する必要はありません。

これらの `display` 設定はコントロールウィンドウからも直接変更できます。

## よくある問題

### タイムラインが表示されない

- トレーニングモードに入っていることを確認してください。
- ゲームが前面にあり、最小化されていないことを確認してください。
- 排他フルスクリーンではなく、ウィンドウまたはボーダーレスを使用してください。
- 設定ファイル、補助プログラム、DLL が `UNI2FrameMeter.exe` と同じフォルダーにあることを確認してください。
- 接続に失敗した場合は、未対応のゲーム版や不足ファイルなどを示すエラーダイアログを確認してください。

### ゲーム更新後に動作しない

今回提供された更新版 EXE では、旧版の戦闘 tick とキャラクタープールのシグネチャが一致せず、キャラクターのオブジェクト構造も変わっていました。旧 GUI はウィンドウを作成する前に例外で終了したため、クラッシュしたように見えました。旧版の SHA-256 は診断用に記録していたもので、不一致による起動拒否ではありません。

この候補版は従来のスキャンを検査付きのネイティブフック設定に置き換え、失敗を表示しますが、関数や構造が変わる更新には対応が必要です。報告にはエラー全文と EXE の SHA-256 を添えてください。エラーログは `%LOCALAPPDATA%\UNI2FrameMeter\logs` に保存され、ダイアログに実際の保存先が表示されます。

### Windowsのセキュリティ警告が表示される

署名されていない個人配布プログラムはSmartScreenの警告を表示する場合があります。本プロジェクトの正式なリリースページからのみダウンロードし、公開されているSHA-256と照合してください。

## ソースからのビルド

まず Python 3 と i686 MinGW-w64 C/C++ コンパイラーで 32-bit の補助プログラムと DLL をビルドします。Linux では、例えば次のコマンドを実行します。

```bash
python3 build_native.py --cc i686-w64-mingw32-gcc-posix --cxx i686-w64-mingw32-g++-posix
```

次に Windows で 64-bit Python 3.12 を使用します。生成した2つのネイティブファイルを `build/native` に配置し、PyInstaller をインストールしてパッケージを作成します。

```powershell
python -m pip install PyInstaller==6.16.0
./build_release.ps1
```

ZIP は `release` に出力されます。[リリースワークフロー](.github/workflows/release.yml) はネイティブビルドと Windows パッケージ作成を別のジョブで実行します。パッケージのビルドにはゲームのインストールは不要です。

## 安全性と免責事項

この版は **DLL を注入し、実行中のゲームメモリに detour ジャンプを設置します**。ディスク上の EXE とゲームリソースは変更しません。元の戦闘関数を通常どおり実行しながら、表示用のゲーム状態を取得します。トレーニングモードでの使用を推奨します。アンチチートやオンライン対戦との互換性は保証していません。

前候補版はユーザーにより実機動作確認済みです。新項目の開発検証では元のゲームを起動していません。パッケージと自作プログラムの確認だけでは、追加した表示の実機精度を確認できません。表示の欠落、誤り、中断があれば、実際のゲームで確認して報告してください。
